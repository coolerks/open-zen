# 工具详解

> 源码目录：`server/src/main/java/com/aiagent/service/tool/project/`  
> 通用约束见"安全约束"章节，各工具的路径参数均为项目内相对路径。

---

## 通用约束

### 路径越界校验

所有工具路径解析经过 `ProjectToolSupport.resolvePathInsideProject()`：

```java
Path resolved = rootPath.resolve(normalized).normalize();
if (!resolved.startsWith(rootPath)) {
    throw new RuntimeException("路径越界，禁止访问项目目录之外的文件。");
}
if (!allowRootPath && resolved.equals(rootPath)) {
    throw new RuntimeException("该操作不允许直接作用于项目根目录。");
}
```

- 路径规范化（`.normalize()`）后检查是否以项目根开头，防止 `../` 穿越
- 部分工具（read/edit/write）禁止直接操作项目根目录本身

### 执行上下文要求

所有 Code Agent 工具的 `execute(arguments)` 无上下文版本均返回固定错误：

```
错误: xxx 仅支持在项目聊天中调用。
```

必须通过 `execute(arguments, ToolExecutionContext context)` 调用，且 `context.projectId()` 非空。

## 1. `bash`

**文件**：`ProjectBashTool.java`  
**功能**：在项目根目录执行 shell 命令，返回退出码与合并输出。

### 输入参数

| 参数 | 类型 | 必填 | 默认值 | 范围 | 说明 |
|------|------|------|--------|------|------|
| `command` | string | ✅ | — | — | 要执行的 shell 命令 |
| `timeoutSec` | integer | ❌ | `30` | `1 ~ 180` | 超时时间（秒） |
| `maxOutputKb` | integer | ❌ | `256` | `16 ~ 2048` | 最大输出大小（KB） |

### 实现细节

**命令执行方式**：

```java
ProcessBuilder builder = new ProcessBuilder("bash", "-lc", command);
builder.directory(rootPath.toFile());
builder.redirectErrorStream(true);  // stdout + stderr 合并
```

- 以 `bash -lc` 方式执行，继承登录 shell 环境（PATH 等）
- stdout 与 stderr 合并为单流，避免双流并发读取死锁

**输出读取（虚拟线程）**：

- 使用 `Thread.startVirtualThread()` 异步读取输出流
- 输出超过 `maxOutputKb * 1024` 字节后截断，`truncated` 标志置 true
- 读取块大小 4096 bytes

**超时处理**：

```java
boolean finished = process.waitFor(timeoutSec, TimeUnit.SECONDS);
if (!finished) {
    process.destroyForcibly();  // 强制终止子进程
}
```

超时后强制终止进程，`outputReader` 等待最多 1 秒后放弃。

### 输出格式

```
命令: <command>
工作目录: <绝对路径>
退出码: <N>          ← 正常结束时
状态: 超时（N 秒）    ← 超时时替换退出码行
提示: 输出超过 NKB，已截断。  ← 仅输出超限时出现

<命令输出内容>
```

若无任何输出，内容部分显示 `(无输出)`。

### 安全约束

- 工作目录固定为项目根目录，无法 `cd` 到项目外执行（但 shell 内部仍可切换目录，这是预期行为）
- 输出上限防止大量输出阻塞 LLM 上下文
- 超时上限 180 秒防止挂起的命令阻塞对话链路

## 2. `read`

**文件**：`ProjectReadTool.java`  
**功能**：分段读取项目内文件，按行号返回内容。

### 输入参数

| 参数 | 类型 | 必填 | 默认值 | 范围 | 说明 |
|------|------|------|--------|------|------|
| `path` | string | ✅ | — | — | 项目内相对路径 |
| `offset` | integer | ❌ | `1` | `≥ 1` | 起始行号（1-based） |
| `limit` | integer | ❌ | `2000` | `1 ~ 2000` | 读取行数 |

### 分页策略

`offset` 小于 1 时自动修正为 1（`Math.max(DEFAULT_OFFSET, offset)`）。  
`limit` 超过 2000 时截断到 2000。

当文件有 N 行而请求了 `offset=1, limit=2000`：
- N ≤ 2000：一次返回全部内容，无分页提示
- N > 2000：返回第 1～2000 行，末尾追加提示：

```
当前内容为1-2000行，共15000行，可传递offset参数继续查看后续内容
```

LLM 根据该提示自行决定是否继续调用。

### 大文件行为

文件用 `Files.readAllLines(filePath, UTF_8)` 一次性加载到内存，再按行号切片。没有流式读取，因此极大文件（例如 100MB）会占用较多内存。实践中 Code Agent 处理的源码文件通常不会达到此量级。

### 单行超长保护

扫描 `startLine` 到 `endLine` 范围内的每一行字节长度：

```java
int lineBytes = line.getBytes(StandardCharsets.UTF_8).length;
if (lineBytes > MAX_SINGLE_LINE_BYTES) {  // 50 * 1024 = 51200 bytes
    int currentKb = (int) Math.ceil(lineBytes / 1024.0d);
    int limitKb   = (int) Math.ceil(MAX_SINGLE_LINE_BYTES / 1024.0d);
    return "第" + lineNo + "行内容共" + currentKb + "kb，超出" + limitKb + "Kb限制，请更换方式读取";
}
```

一旦发现单行超过 **50KB**，立即返回错误信息，不返回任何文件内容。

### 输出格式

```
文件: src/main/java/App.java
当前内容为1-100行，共350行

1| package com.example;
2| 
3| public class App {
...
100| }

当前内容为1-100行，共350行，可传递offset参数继续查看后续内容
```

每行前缀格式：`<行号>| <内容>`

### 安全约束

- 禁止读取目录（`Files.isDirectory` 检查）
- 文件不存在时返回 `"文件不存在: <path>"`，不抛异常
- 单行 50KB 上限防止 base64 编码的二进制文件撑爆 LLM 上下文

## 3. `edit`

**文件**：`ProjectEditTool.java`  
**功能**：通过精确字符串替换修改现有文件（Code Agent 最主要的代码修改方式）。

### 输入参数

| 参数 | 类型 | 必填 | 默认值 | 范围 | 说明 |
|------|------|------|--------|------|------|
| `path` | string | ✅ | — | — | 项目内相对文件路径 |
| `oldText` | string | ✅ | — | — | 待替换的原始文本（精确匹配，区分大小写） |
| `newText` | string | ✅ | — | — | 替换后的文本（可为空字符串，实现删除效果） |
| `replaceAll` | boolean | ❌ | `false` | — | `false`=只替换首个，`true`=替换全部 |
| `expectedOccurrences` | integer | ❌ | `-1`（不校验） | `≥ 0` | 期望命中次数，不符合则拒绝替换 |

### 实现细节

**匹配计数**：

```java
private int countOccurrences(String text, String target) {
    int count = 0, index = 0;
    while ((index = text.indexOf(target, index)) >= 0) {
        count++;
        index += target.length();
    }
    return count;
}
```

用 `String.indexOf` 精确查找，区分大小写，不支持正则。

**期望次数校验**：

```java
if (expectedOccurrences >= 0 && expectedOccurrences != hitCount) {
    return "命中次数不符合预期，实际命中 " + hitCount + " 次，expectedOccurrences=" + expectedOccurrences;
}
```

LLM 可以传 `expectedOccurrences=1` 来防止误替换同名字符串。

**替换执行**：

- `replaceAll=false`（默认）：手动实现 `replaceFirst`，避免 `String.replaceFirst` 将 oldText 当正则处理
- `replaceAll=true`：调用 `String.replace(oldText, newText)`（字面量替换，非正则）

**文件写入**：调用 `ProjectToolSupport.writeText(filePath, updatedContent, false)`，走原子写文件流程（见下方 `write` 工具的写入机制描述）。

### 未匹配处理

```
未找到需要替换的 oldText。
```

不会修改文件，直接返回错误，LLM 需要重新确认 oldText 内容。

### 输出格式

成功：
```
编辑成功: src/main/java/App.java，共替换 1 处文本。
```

失败：
```
未找到需要替换的 oldText。
命中次数不符合预期，实际命中 3 次，expectedOccurrences=1
参数 oldText 不能为空字符串。
```

### 安全约束

- 文件必须已存在（通过 `ProjectToolSupport.readText` 读取，不存在则抛异常）
- 路径越界检查（`resolvePathInsideProject(rootPath, rawPath, false)`，`allowRootPath=false`）
- `oldText` 不能为空（避免意外全量替换）

## 4. `write`

**文件**：`ProjectWriteTool.java`  
**功能**：创建新文件或覆盖已有文件，写入指定内容。

### 输入参数

| 参数 | 类型 | 必填 | 默认值 | 范围 | 说明 |
|------|------|------|--------|------|------|
| `path` | string | ✅ | — | — | 项目内相对文件路径 |
| `content` | string | ✅ | — | — | 完整文件内容（覆盖写入） |
| `createParents` | boolean | ❌ | `true` | — | 父目录不存在时是否自动创建 |

### 自动创建父目录

`createParents=true`（默认）时调用 `Files.createDirectories(parent)` 递归创建所有缺失的父目录。  
`createParents=false` 时若父目录不存在则返回 `"目标目录不存在。"`。

### 原子写文件机制

`ProjectToolSupport.writeText()` 使用临时文件 + 重命名保证原子性：

```java
Path tempPath = Files.createTempFile(parent, ".openzen-project-tool-", ".tmp");
Files.writeString(tempPath, content, UTF_8, TRUNCATE_EXISTING);
try {
    Files.move(tempPath, filePath, REPLACE_EXISTING, ATOMIC_MOVE);
} catch (AtomicMoveNotSupportedException ex) {
    Files.move(tempPath, filePath, REPLACE_EXISTING);  // 降级为非原子
}
```

- 先写临时文件，再原子 `move` 到目标路径
- 跨文件系统时自动降级为非原子 move
- `finally` 块清理临时文件，避免残留

### 禁止覆盖目录

```java
if (Files.exists(filePath) && Files.isDirectory(filePath)) {
    return "目标路径是目录，无法覆盖写入文件。";
}
```

### 输出格式

成功：
```
写入成功: src/config/app.yaml（1024 bytes）
```

失败：
```
参数 path 不能为空。
参数 content 不能为空。
目标路径是目录，无法覆盖写入文件。
目标目录不存在。
```

### 安全约束

- 路径越界检查（`allowRootPath=false`，不允许直接写项目根目录）
- 不对写入内容大小设限（LLM 上下文窗口本身是实际限制）

## 5. `grep`

**文件**：`ProjectGrepTool.java`  
**功能**：用正则表达式搜索项目文件内容，支持 glob 文件过滤。

### 输入参数

| 参数 | 类型 | 必填 | 默认值 | 范围 | 说明 |
|------|------|------|--------|------|------|
| `pattern` | string | ✅ | — | — | Java 正则表达式 |
| `glob` | string | ❌ | `**/*` | — | 文件路径 glob 过滤 |
| `path` | string | ❌ | 项目根目录 | — | 搜索起始目录（相对路径） |
| `ignoreCase` | boolean | ❌ | `false` | — | 是否忽略大小写 |
| `limit` | integer | ❌ | `200` | `1 ~ 1000` | 最大命中条数 |

### 实现细节

**glob 匹配**：

```java
PathMatcher globMatcher = FileSystems.getDefault().getPathMatcher("glob:" + glob);
```

同时对 `relativeFromRoot` 和 `relativeFromSearchRoot` 两个路径做匹配，兼容不同起始目录的场景。

**二进制文件跳过**：

扩展名命中以下列表时跳过：

```
png jpg jpeg gif webp bmp ico pdf
zip 7z rar gz tar jar war
mp3 mp4 mov avi
woff woff2 ttf otf
exe dll so dylib class
```

**文件大小限制**：超过 **2MB** 的文件跳过（`MAX_FILE_SIZE_BYTES = 2 * 1024 * 1024`）。

**行预览截断**：

```java
private static final int MAX_LINE_PREVIEW = 220;
```

命中行文本经过规范化（tab/CR/LF 替换为空格，多空格合并）后，超过 220 字符追加 `...`。

**达到 limit 后立即停止**：遍历文件时 `hits.size() >= limit` 即 break，不继续扫描。

### 输出格式

```
正则: TODO|FIXME
glob: **/*.java
命中: 15（已按 limit=200 截断）
扫描文件: 120，跳过文件: 3

1. src/main/java/App.java:42 | // TODO: 优化查询性能
2. src/main/java/Service.java:87 | // FIXME: 空指针未处理
...
```

无命中时：
```
未找到匹配内容。
```

### 安全约束

- 起始目录做路径越界检查（`allowRootPath=true`，允许从根目录开始搜索）
- 文件大小上限 2MB 防止大文件阻塞遍历
- 二进制文件自动跳过，防止乱码污染结果
- `limit` 上限 1000 条

## 6. `glob`

**文件**：`ProjectGlobTool.java`  
**功能**：按 glob 模式在项目中查找文件/目录路径，结果按修改时间倒序排列。

### 输入参数

| 参数 | 类型 | 必填 | 默认值 | 范围 | 说明 |
|------|------|------|--------|------|------|
| `pattern` | string | ✅ | — | — | glob 表达式（如 `**/*.ts`、`src/**/*.java`） |
| `path` | string | ❌ | 项目根目录 | — | 搜索起始目录（相对路径） |
| `limit` | integer | ❌ | `200` | `1 ~ 1000` | 最大返回数量 |
| `includeDirectories` | boolean | ❌ | `false` | — | 是否包含目录条目 |

### 排序规则

```java
hits.sort(Comparator
    .comparingLong(PathHit::lastModifiedMillis).reversed()
    .thenComparing(PathHit::path));
```

主排序：修改时间倒序（最近修改的文件排前面）；同一时间戳内按路径字典序升序。

### glob 匹配细节

```java
PathMatcher matcher = FileSystems.getDefault().getPathMatcher("glob:" + pattern.trim());
```

同时对 `projectRoot.relativize(path)` 和 `searchRoot.relativize(path)` 做匹配，起始目录相对路径下的 `**/*.ts` 和根目录相对路径下的 `src/**/*.ts` 均能命中对应文件。

### 输出格式

```
匹配模式: **/*.ts
起始目录: .
命中数量: 42（已按 limit=200 截断）

file web/src/components/Chat.tsx
file web/src/pages/ProjectsPage.tsx
dir  web/src/components
...
```

条目前缀：`file ` 或 `dir `（`includeDirectories=true` 时才出现目录条目）。

无匹配时：
```
未匹配到任何路径。
```

### 安全约束

- 起始目录越界检查（`allowRootPath=true`）
- glob 模式不合法时返回明确错误信息，不抛异常
- `limit` 上限 1000

## 7. `list`

**文件**：`ProjectListTool.java`  
**功能**：列出目录条目，支持 glob 过滤、递归遍历、隐藏文件过滤。

### 输入参数

| 参数 | 类型 | 必填 | 默认值 | 范围 | 说明 |
|------|------|------|--------|------|------|
| `path` | string | ❌ | 项目根目录 | — | 起始目录（相对路径） |
| `glob` | string | ❌ | `*`（非递归）/ `**/*`（递归） | — | 路径 glob 过滤 |
| `recursive` | boolean | ❌ | `false` | — | 是否递归列出子目录 |
| `includeHidden` | boolean | ❌ | `false` | — | 是否包含隐藏文件/目录（`.` 开头） |
| `includeFiles` | boolean | ❌ | `true` | — | 是否包含文件 |
| `includeDirectories` | boolean | ❌ | `true` | — | 是否包含目录 |
| `limit` | integer | ❌ | `200` | `1 ~ 2000` | 最大返回数量 |

`includeFiles` 和 `includeDirectories` 不能同时为 `false`。

### 递归深度控制

```java
int maxDepth = recursive ? Integer.MAX_VALUE : 1;
Files.walk(searchRoot, maxDepth)
```

- `recursive=false`（默认）：只列出直接子条目（`maxDepth=1`）
- `recursive=true`：完整递归遍历（`maxDepth=Integer.MAX_VALUE`）

### 隐藏文件过滤

```java
private boolean containsHiddenSegment(String relativePath) {
    String[] segments = relativePath.split("/");
    for (String segment : segments) {
        if (segment.startsWith(".")) return true;
    }
    return false;
}
```

路径任意片段以 `.` 开头均视为隐藏（包括 `.git/`、`.env` 等）。`includeHidden=false` 时过滤。

### glob 默认值

用户未传 `glob` 时：
- `recursive=false`：默认 `*`（匹配当前目录直接子条目）
- `recursive=true`：默认 `**/*`（匹配所有层级条目）

内部构建两个 matcher：`glob:<pattern>` 和（`**/*` 时额外加）`glob:**`，兼容 Java PathMatcher 对根目录文件匹配的差异。

### 排序规则

```java
entries.sort(Comparator
    .comparingLong(ListEntry::modifiedMillis).reversed()
    .thenComparing(ListEntry::path));
```

与 `glob` 相同：修改时间倒序，同时间按路径字典序。

### 输出格式

```
目录: src/main/java
glob: *
递归: 否
匹配数量: 5（已按 limit=200 截断）
扫描条目: 5

1. file src/main/java/App.java (2048 bytes) [mtime 2025-06-01 10:30:00]
2. dir  src/main/java/controller [mtime 2025-06-01 09:00:00]
3. dir  src/main/java/service [mtime 2025-05-31 20:00:00]
...
```

- 文件显示字节数：`(N bytes)`
- 目录不显示大小
- 修改时间格式：`yyyy-MM-dd HH:mm:ss`（服务器本地时区）
- 读取文件属性失败时，`size=0`，`mtime` 显示 `-`

空目录或无匹配时：
```
目录为空或没有匹配项。
```

### 安全约束

- 起始目录越界检查（`allowRootPath=true`）
- `limit` 上限 2000（比 glob/grep 更大，适合列目录场景）
- 隐藏文件默认不显示，防止意外暴露 `.env`、`.git` 等敏感目录

## 工具设计要点

| 要点 | 说明 |
|------|------|
| 工具结果即 LLM 输入 | 输出文本可读性直接影响 LLM 下一步推理质量 |
| 分页避免上下文爆炸 | `read` 的 2000 行上限和单行 50KB 保护确保单次输入可控 |
| 截断提示 | 所有工具在达到 limit 时明确提示已截断，LLM 可发起追加查询 |
| 原子写文件 | `edit`/`write` 通过临时文件 + rename 防止写入中断导致文件损坏 |
| 越界防护 | 统一在 `ProjectToolSupport` 集中处理，各工具无需单独校验 |
| 二进制过滤 | `grep` 跳过已知二进制扩展名，避免乱码干扰 |
