# 项目聊天

> 源码参考：`ProjectChatController.java`、`ChatService.java`、`schema.sql`

---

## 一、与普通聊天的本质区别

Open Zen 中存在两套并行的聊天体系：

| | 普通聊天 | 项目聊天 |
|---|---|---|
| 路由路径 | `/api/chat/*` | `/api/projects/{projectId}/chat/*` |
| 控制器 | `ChatController` | `ProjectChatController` |
| 会话 `project_id` | `NULL` | 项目 ID（非空字符串） |
| Code Agent 工具 | **不下发** | **按白名单下发** |
| 会话列表过滤 | `WHERE project_id IS NULL` | `WHERE project_id = ?` |

**两套接口完全隔离**：`ChatService.getSession()` 发现 `project_id` 非空时会直接抛异常，防止普通聊天接口误操作项目会话，反之亦然。

```java
// ChatService.getSession()
if (isProjectSession(session)) {
    throw new RuntimeException("该会话属于项目聊天，请使用项目聊天接口访问。");
}

// ChatService.getProjectSession()
if (!normalizedProjectId.equals(normalizeNullableProjectId(session.getProjectId()))) {
    throw new RuntimeException("会话不属于当前项目: " + id);
}
```

## 二、会话 project_id 绑定

### 数据库字段

```sql
-- chat_session 表
project_id  VARCHAR(64)  -- 空表示普通聊天会话
```

- 普通聊天：`project_id = NULL`
- 项目聊天：`project_id = <项目ID>`（创建时写入，不可修改）

### 创建时绑定

```java
// ChatService.createProjectSession()
public ChatSession createProjectSession(String projectId, String title, Long agentId, Boolean temporary) {
    String normalizedProjectId = normalizeProjectId(projectId);
    projectService.getById(normalizedProjectId);  // 存在性校验
    return createSessionInternal(..., normalizedProjectId, ...);
}
```

`normalizeProjectId` 去除首尾空白，`projectService.getById` 确保项目存在，否则拒绝创建。

### 执行时注入

消息发送时，`projectId` 通过 `ToolExecutionContext` 传递给工具：

```java
// ChatService.runCompletionWithTools()
ToolExecutionContext toolExecutionContext = new ToolExecutionContext(
    sessionId,
    normalizeNullableProjectId(context.session().getProjectId())
);
```

工具通过 `ProjectToolSupport.requireProjectId(context)` 取出并校验 projectId，再调用 `ProjectFilesystemService.resolveProjectRootPathForWatch(projectId)` 获取项目根目录的本地绝对路径。

## 三、接口路径完整列表

所有接口前缀：`/api/projects/{projectId}/chat`

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/sessions` | 创建项目会话（绑定 projectId） |
| `GET` | `/sessions` | 列出当前项目的所有非临时会话 |
| `GET` | `/tools` | 获取项目聊天可用工具列表（含 Code Agent 工具） |
| `GET` | `/sessions/{id}` | 获取指定会话 |
| `PATCH` | `/sessions/{id}` | 更新会话（标题/模型/智能体/工具白名单） |
| `DELETE` | `/sessions/{id}` | 删除会话（级联删除消息） |
| `POST` | `/sessions/{id}/auto-title` | 自动生成会话标题 |
| `GET` | `/sessions/{sessionId}/messages` | 获取会话消息列表 |
| `GET` | `/sessions/{sessionId}/context` | 获取会话上下文 Token 用量统计 |
| `DELETE` | `/sessions/{sessionId}/messages/{messageId}` | 删除指定消息 |
| `POST` | `/sessions/{sessionId}/tool-approval` | 提交工具调用授权（非流式） |
| `POST` | `/sessions/{sessionId}/tool-approval/stream` | 提交工具调用授权（SSE 流式） |
| `POST` | `/send` | 非流式发送消息 |
| `POST` | `/stream` | SSE 流式发送消息 |

> 注意：`{projectId}` 是 URL 路径变量，不是 session 的 project_id 字段值，但两者含义相同，均为项目唯一标识。

## 四、项目上下文注入

### 工具调用链路中的上下文

```
POST /api/projects/{projectId}/chat/stream
  → ProjectChatController.stream(projectId, request)
  → ChatService.streamProjectMessage(projectId, request)
      → sendMessageInternal(request, normalizeProjectId(projectId))
          → prepareSendContext(request, ..., expectedProjectId)
              → resolveScopedSession(sessionId, expectedProjectId)  // 校验会话归属
              → resolveAvailableTools(..., projectChat=true)       // 注入 projectOnly 工具
          → runCompletionWithTools(...)
              → ToolExecutionContext(sessionId, projectId)         // 传递给工具
```

### 会话归属校验

`resolveScopedSession(sessionId, expectedProjectId)` 逻辑：
- `expectedProjectId == null`：普通聊天，要求 `session.projectId == null`
- `expectedProjectId != null`：项目聊天，要求 `session.projectId == expectedProjectId`

两者不匹配均抛异常，确保会话不能跨项目操作。

## 五、工具列表差异（projectOnly 机制）

### 过滤逻辑

```java
// ChatService.resolveAvailableTools()
List<ToolDefinition> allTools = toolRegistry.getAllTools().stream()
    .filter(tool -> projectChat || !tool.projectOnly())  // 核心过滤
    .toList();
```

- `projectChat = true`（项目聊天）：所有工具均可见
- `projectChat = false`（普通聊天）：`projectOnly() == true` 的工具被过滤

### 各工具的 projectOnly 值

| 工具 | `projectOnly()` | 说明 |
|------|----------------|------|
| `bash` | `true` | 仅项目聊天 |
| `read` | `true` | 仅项目聊天 |
| `edit` | `true` | 仅项目聊天 |
| `write` | `true` | 仅项目聊天 |
| `grep` | `true` | 仅项目聊天 |
| `glob` | `true` | 仅项目聊天 |
| `list` | `true` | 仅项目聊天 |
| `getCurrentDate` | `false` | 两种聊天均可用 |
| `searchConversationMemory` | `false` | 两种聊天均可用（需开启记忆） |

### 工具白名单（enabled_tool_names）

会话级工具白名单存储在 `chat_session.enabled_tool_names`（JSON 数组字符串）：

- `NULL` 或空：不限制，下发全部符合条件的工具
- 非空 JSON 数组：只下发列表内的工具

项目聊天在调用 `sanitizeToolNames(names, projectChat=true)` 时，会同时允许 `projectOnly=true` 的工具进入白名单；普通聊天调用时 `projectOnly=true` 的工具会被静默过滤。

```java
// ChatService.sanitizeToolNames()
.filter(tool -> {
    return projectChat || !tool.projectOnly();
})
```

### 工具列表接口

- 普通聊天工具列表：`GET /api/chat/tools`
  - 过滤掉 `projectOnly=true` 的工具
- 项目聊天工具列表：`GET /api/projects/{projectId}/chat/tools`
  - 包含所有工具，含 7 个 Code Agent 工具

## 六、工具调用授权流

项目聊天完整支持与普通聊天相同的工具授权机制：

1. **需要用户授权模式**（默认）：工具调用前暂停，等待用户逐条批准/拒绝
2. **自动调用模式**：工具调用直接执行，无需用户确认

Code Agent 工具（bash/read/edit/write/grep/glob/list）均未覆盖 `bypassUserApproval()`，默认返回 `false`，即在"需要用户授权"模式下均需要用户授权。

授权接口：

```
POST /api/projects/{projectId}/chat/sessions/{sessionId}/tool-approval
POST /api/projects/{projectId}/chat/sessions/{sessionId}/tool-approval/stream
```

请求体：

```json
{
  "assistantMessageId": 123,
  "approved": true,
  "maxToolRounds": 100
}
```

## 七、工具调用轮次控制

```java
// ChatService 常量
private static final int DEFAULT_MAX_TOOL_ROUNDS = 100;
private static final int MAX_TOOL_ROUNDS_UPPER_BOUND = 500;
```

- 默认最多 100 轮工具调用
- 前端可通过 `ChatSendRequest.maxToolRounds` 覆盖，上限 500
- 超限后写入提示消息并停止：`"工具调用轮次超限（上限 N 轮），已停止处理。"`
