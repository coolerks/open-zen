# 模型自动发现 (Model Auto-Discovery)

模型自动发现模块通过标准 API 接口，自动从供应商获取最新的模型列表及详细元数据。

## 1. 架构设计：适配器模式 (Adapter Pattern)

后端采用 `ModelCatalogService` 作为中央调度器，通过不同的 `ModelCatalogAdapter` 实现类处理不同供应商的 API。

### 类层次结构
*   `ModelCatalogAdapter` (接口)
    *   `AbstractOpenAiCompatibleModelCatalogAdapter` (抽象基类)
        *   `OpenAiModelCatalogAdapter` (通用 OpenAI 实现)
        *   `OpenRouterModelCatalogAdapter` (针对 OpenRouter 优化的增强实现)

## 2. 解析逻辑：增强字段提取

### 通用解析
基类 `AbstractOpenAiCompatibleModelCatalogAdapter` 负责解析标准的 `/v1/models` 响应。
*   **正则解析器**：`TOKEN_NUMBER_PATTERN` 用于从 ID 或描述中提取上下文长度（如：将 `128k` 解析为 `131072`）。
    ```java
    // 关键正则：[0-9]+(\.[0-9]+)?(k|m|K|M)?
    ```

### OpenRouter 增强
`OpenRouterModelCatalogAdapter` 能够提取 OpenRouter 独有的元数据：
*   **计费信息**：`pricing.prompt` (输入价格) 和 `pricing.completion` (输出价格)。
*   **上下文长度**：直接读取 `context_length` 字段。
*   **支持参数**：如 `supported_parameters` 中的能力描述。

## 3. API 交互流程

| 步骤 | 说明 |
| :--- | :--- |
| 1. 前端触发 | 用户点击模型管理页面的“发现模型 (Discover Models)” 按钮。 |
| 2. 后端请求 | `/api/models/discover/{providerId}` GET 请求发送至后端。 |
| 3. 适配器调度 | `ModelCatalogService` 根据供应商 Base URL 匹配对应适配器。 |
| 4. 外部调用 | 适配器解密 API Key，并请求供应商的 `/v1/models` 接口。 |
| 5. 结果聚合 | 适配器将外部响应转换为统一的 `ModelDiscoveryItemResponse` DTO。 |
| 6. 前端展示 | 返回转换后的列表，用户勾选需要的模型进行导入/更新。 |

## 4. 关键响应 DTO (`ModelDiscoveryItemResponse`)

```java
public class ModelDiscoveryItemResponse {
    private String id;          // 模型原始 ID (如 gpt-4)
    private String name;        // 模型名称
    private Integer contextWindow; // 解析后的上下文窗口
    private BigDecimal inputPrice;  // 解析后的输入价格
    private BigDecimal outputPrice; // 解析后的输出价格
    private Set<String> capabilities; // 解析后的能力集 (CHAT/IMAGE/etc.)
}
```
