# 会话模型策略 (Session Model Strategy)

会话模型策略负责在用户与 AI 交互时，确定当前会话所使用的模型，并确保用户偏好能够在不同设备上得到一定程度的维持。

## 1. 前端偏好持久化 (`chatStore.ts`)

系统使用 Zustand 的持久化中间件 (`persist`) 将关键偏好保存至浏览器的 `localStorage` 中。

*   **Key**: `chat-storage`
*   **存储字段**: `lastSelectedModelId` (最近一次选中的模型 ID)。
*   **作用**: 当用户刷新页面或重新打开浏览器时，系统会自动恢复上一次使用的模型，提升用户体验。

## 2. 模型解析与继承机制

在聊天页面 (`ChatPage.tsx`) 或 API 请求时，模型的确定遵循以下优先级：

1.  **URL 参数 / 会话 ID 指定**：如果当前 URL 带有特定的会话 ID，则从数据库加载该会话绑定的模型。
2.  **本地持久化偏好**：如果是一个新会话，则读取 `localStorage` 中的 `lastSelectedModelId`。
3.  **默认启用模型**：如果本地偏好为空（如首次使用），系统会自动选取当前系统中第一个已启用的模型。

## 3. 后端降级与验证策略

在后端执行 AI 请求之前，`AiModelService` 会对模型有效性进行二次验证：

### 降级逻辑流程
*   **输入模型检测**：验证用户请求的模型 ID 是否存在于数据库中且处于 `isEnabled = true` 状态。
*   **动态降级**：若请求的模型不可用，后端会回退到供应商配置中的“默认模型”。
*   **异常处理**：若系统中没有任何已启用的模型，后端将抛出自定义异常，告知用户“未找到可用的 AI 模型”。

## 4. 前端 UI 响应

### 模型切换交互
*   **Store 更新**：用户从模型下拉菜单中选择新模型时，同步更新 `useChatStore` 的 `selectedModelId`。
*   **侧边栏状态**：会话侧边栏展示当前正在使用的模型图标和名称，直观呈现当前上下文。
*   **全局同步**：由于使用 Zustand，模型切换会立即反映在所有依赖该状态的组件中（如：计费预估组件、历史消息列表）。
