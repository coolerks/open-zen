# 消息管理实现

Open Zen 将每一条消息视为一次带有环境快照的原子记录，确保对话历史在模型或智能体配置变更后仍可追溯。

## 数据模型 (chat_message 表)

| 字段 | 说明 |
| :--- | :--- |
| `role` | `user`, `assistant`, `system`, `tool` |
| `content` | 消息正文 |
| `image_urls` | 图片输入（JSON 数组，含 DataURL 或链接） |
| `reasoning_content` | 模型的推理思考过程 |
| `reasoning_duration_ms` | 推理耗时（毫秒） |
| `model_id`, `model_name` | **生成快照**：记录该消息生成时所选的模型 |
| `agent_id`, `agent_name`, `avatar_*` | **智能体快照**：记录该消息生成时关联的智能体及其当时的头像/名称 |
| `token_usage`, `cost_usd` | **资源消耗**：统计该消息产生的 Token 及其估算的费用 |

## 关键功能实现

### 1. 消息 CRUD
- **读取**：`GET /api/chat/sessions/{sessionId}/messages` 返回按时间升序排列的消息。
- **删除**：`DELETE /api/chat/sessions/{sessionId}/messages/{messageId}` 删除单条记录。
- **更新**：目前主要通过克隆会话或重新生成实现间接“编辑”。

### 2. 推理内容与耗时
- **流式接收**：`reasoning` 事件下发增量推理内容。
- **展示**：前端默认将推理内容折叠展示，并显示计算出的耗时（如“思考 12秒”）。
- **计算策略 (ChatService.java)**：后端通过首字下发时间减去请求开始时间，得到精确的推理耗时并入库。

### 3. 多模态（图片）输入
- **前端处理**：支持粘贴、拖拽或点击上传图片。
- **发送格式**：图片以 `image_urls` JSON 数组随请求发送。
- **Token 估算**：后端对每张图片按固定 600 Tokens 比例进行粗略预估，用于上下文窗口统计。

### 4. 费用统计
- **模型单价**：每次生成时，系统会实时读取当前模型的 `input_price` 和 `output_price`。
- **成本持久化**：计算结果 `cost_usd` 直接存入 `chat_message` 表，避免历史账单随模型调价而波动。

## 关键文件定位

- **前端**：`web/src/pages/ChatPage.tsx` (消息渲染组件), `web/src/types/index.ts` (ChatMessage 接口定义)
- **后端**：`ChatService.applyUsageSnapshot` (费用计算), `ChatService.applyAgentSnapshot` (快照注入)
- **数据库表**：`chat_message`
