# 上下文与参数管理

Open Zen 实现了精细化的聊天上下文控制与参数透传链路，确保在不同模型间切换时能够保持对话连贯性，并根据模型限制自动优化上下文窗口。

## 1. 上下文压缩策略 (Context Compression)

为了避免超出大模型的上下文窗口（Context Window），后端 `ChatService` 在发送请求前会执行 `compressHistoryIfNeeded` 逻辑。

### 核心参数
- `DEFAULT_CONTEXT_WINDOW_TOKENS`: 128,000 (默认兜底)
- `MIN_PROMPT_BUDGET_TOKENS`: 1,024 (最小上下文保留预算)
- `DEFAULT_RESERVED_OUTPUT_TOKENS`: 4,096 (默认预留输出空间)

### 压缩逻辑
1. **获取模型限制**：从 `AiModel` 实体中获取 `contextWindowTokens`，若未配置则使用默认值。
2. **计算预留空间**：
   - 优先使用请求中指定的 `max_tokens`。
   - 若未指定，则根据模型 `maxCompletionTokens` 启发式计算（通常预留 $1/8$ 窗口或 4096）。
   - 硬性约束：预留输出至少 256 tokens，且必须给 Prompt 留下至少 1024 tokens。
3. **滑动窗口裁剪**：
   - 使用 `TokenEstimator` 估算当前历史消息的总 Token 数。
   - 若超出预算，按 **最老消息优先** 的原则逐条删除，直到符合窗口要求。
   - 裁剪结果包含：保留的消息列表、删除的消息数、预估使用的 Token 数。

### Token 估算算法
- **文本**：基于字符长度启发式估算（`TokenEstimator.estimateTextTokens`）。
- **图片**：每张图片固定计为 600 tokens (`ESTIMATED_IMAGE_TOKENS`)。
- **结构化开销**：每条消息额外增加 4 tokens 用于 Role 和边界标识。

## 2. 参数透传链路

系统支持从前端 UI 到后端 API 的完整参数配置透传，允许用户在发送消息时覆盖模型默认行为。

### 支持的参数
| 参数名 | 类型 | 说明 | 优先级 |
| :--- | :--- | :--- | :--- |
| `temperature` | Double | 采样温度，控制输出随机性 | 请求指定 > 模型默认 (0.7) |
| `max_tokens` | Integer | 最大输出长度限制 | 请求指定 > 模型默认 > 自动限制 |
| `top_p` | Double | 核采样参数 | 模型默认 |
| `stream` | Boolean | 是否流式输出 | SSE 接口固定为 true |

### 链路流转
1. **前端 (chatStore.ts)**：在 `sendMessage` 中收集 `options`（含 temperature, maxTokens）。
2. **后端 (ChatSendRequest.java)**：DTO 接收参数并传递给 `prepareSendContext`。
3. **上下文准备 (ChatService.java)**：
   - `prepareSendContext` 方法解析模型实体中的 `defaultParams`。
   - 使用请求参数覆盖模型默认参数。
   - `buildRequest` 将最终参数组装进 `ChatCompletionRequest`。
4. **客户端 (OpenRouterClient.java)**：将请求序列化为 JSON 发往供应商 API。

## 3. 上下文统计 API

前端通过专门的端点获取当前会话的上下文健康状态，用于在 UI 上显示“上下文进度条”。

- **端点**：`GET /api/chat/sessions/{id}/context`
- **响应格式 (`ChatSessionContextStatsResponse`)**：
  ```json
  {
    "contextUsedTokens": 1250,
    "contextWindowTokens": 128000,
    "contextUsageRatio": 0.0097,
    "sessionCostUsd": 0.045,
    "sessionPromptTokens": 8500,
    "sessionCompletionTokens": 3200
  }
  ```

## 4. 跨会话记忆 (Memory)

记忆功能作为一种特殊的“上下文扩展”，通过工具调用实现。

- **开关逻辑**：`request.memoryEnabled`。
- **实现原理**：
  - 当记忆开启时，系统会向模型注入 `searchConversationMemory` 工具。
  - 模型根据需要主动调用该工具检索历史会话片段。
  - 检索结果作为 `tool` 消息插入上下文，实现跨会话的知识透传。
- **约束**：临时聊天 (`temporary: true`) 模式下，记忆功能强制关闭。
