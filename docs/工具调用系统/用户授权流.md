# 用户授权流 (User Approval Flow)

为了平衡 AI 的自动化能力与系统的安全性，Open Zen 实现了一套可交互的工具授权机制。

## 核心流程

1.  **中断决策 (Backend)**:
    - 后端检测到 `tool_call` 请求调用的方法被标记为非免授权工具（`bypassUserApproval = false`）。
    - 检查当前请求是否已携带授权凭证。若无，后端向 SSE 通道发送 `toolApprovalRequired: true` 信号，并物理断开当前会话连接。
2.  **前端交互 (Frontend)**:
    - 前端 `ChatPage.tsx` 接收到 `toolApprovalRequired` 信号。
    - **UI 渲染**: `MessageCard` 组件将 `assistant` 角色下的 `tool_calls` 渲染为“待授权”卡片。
    - **用户动作**: 用户点击“允许”或“拒绝”。
3.  **授权恢复 (Recovery)**:
    - **允许**: 前端调用 `/api/chat/tool-approval` 接口。
    - 后端接收到确认指令后，重新启动 `ChatService.runCompletionWithTools` 逻辑。
    - 此时后端拥有了显式授权，会执行真实的工具逻辑并将结果作为 `tool` 角色消息填入上下文，继续后续生成。
    - **拒绝**: 结果将作为一条“用户拒绝执行”的消息回传给模型。

## 消息聚合逻辑 (前端)

在 React 渲染层，为了避免“碎石化”的消息展示，`buildDisplayMessages` 函数会执行逻辑聚合：

- 它会将紧随在 `assistant` 消息后的多条 `tool` 角色消息（即工具执行结果）合并到同一个 `assistant` 消息卡片中展示。
- 每个工具调用在卡片中以单独的“步骤”显示其入参、状态（Pending/Running/Success/Failed）以及输出结果。

## 关键文件路径

- **前端授权动作**: `web/src/store/chatStore.ts` (方法: `resolveToolApproval`)
- **待授权卡片逻辑**: `web/src/pages/ChatPage.tsx` (组件: `ToolCallSteps`)
- **后端授权 API**: `server/src/main/java/com/aiagent/controller/ChatController.java` (接口: `/tool-approval`)
- **后端执行拦截**: `server/src/main/java/com/aiagent/service/ChatService.java`
