# AI 聊天工具功能迭代说明

## 1. 迭代目标
本次迭代在现有“模型管理 + 基础聊天”基础上，新增以下能力：

- 聊天流式输出（SSE）
- 自动会话标题
- 视觉模型图片输入
- 模型“支持推理”开关与推理内容折叠展示
- Markdown 与数学公式（KaTeX）渲染
- 会话管理（重命名、复制、删除二次确认）
- 消息分支会话（从任意消息创建新会话）
- 消息删除（二次确认）
- 消息记录并展示“生成模型”
- 自定义智能体（行为与特征定义）
- 进入会话自动带出最后使用模型
- UI 参考新版 ChatGPT 的布局与交互结构

## 2. 数据库变更
已在 `server/src/main/resources/schema.sql` 完成 DDL 扩展，且为表/字段补充中文注释。

### 2.1 新增字段
- `ai_model.supports_reasoning`：模型是否支持推理输出
- `chat_session.agent_id`：会话绑定智能体
- `chat_session.parent_session_id`：父会话 ID（复制/分支来源）
- `chat_session.parent_message_id`：分支起点消息 ID

### 2.2 新增表

## 3. 后端能力

### 3.1 SSE 流式聊天
- 接口：`POST /api/chat/stream`
- 实现位置：
  - `server/src/main/java/com/aiagent/controller/ChatController.java`
  - `server/src/main/java/com/aiagent/service/ChatService.java`
  - `server/src/main/java/com/aiagent/service/OpenRouterClient.java`

SSE 事件：
- `start`：开始生成
- `delta`：正文增量
- `reasoning`：推理内容增量
- `done`：结束（含 `messageId`、`modelName`、`tokenUsage`、`title`）
- `error`：异常

### 3.2 自动标题
- 首轮用户消息写入后，如果标题仍是默认“新会话”，自动截取文本生成标题。
- 实现位置：`ChatService#applyAutoTitleIfNeeded`

### 3.3 视觉消息
- `ChatSendRequest` 新增 `images` 字段。
- 对支持视觉模型将消息组装为 OpenAI/OpenRouter 兼容的 `content: [{type:text},{type:image_url}]`。
- 实现位置：`ChatService#buildVisionContent`

### 3.4 会话与消息管理
- 复制会话：`POST /api/chat/sessions/{id}/copy`
- 分支会话：`POST /api/chat/sessions/{id}/branch`
- 更新会话（标题/模型/智能体）：`PATCH /api/chat/sessions/{id}`
- 删除消息：`DELETE /api/chat/sessions/{sessionId}/messages/{messageId}`

### 3.5 智能体管理
- 控制器：`server/src/main/java/com/aiagent/controller/CustomAgentController.java`
- 服务：`server/src/main/java/com/aiagent/service/CustomAgentService.java`
- 接口：
  - `GET /api/agents`
  - `GET /api/agents/enabled`
  - `POST /api/agents`
  - `PUT /api/agents/{id}`
  - `PATCH /api/agents/{id}/toggle`
  - `DELETE /api/agents/{id}`

## 10. 本轮补充（2026-03-13）

### 10.1 普通聊天工具授权续跑改为流式返回
- 问题现象：
  - 普通聊天页在用户点击“允许/拒绝”后，前端会一直等待同步接口返回。
  - 工具结果回填给模型后，助手正文会一次性落到页面，而不是继续按 SSE 增量输出。
- 修复方式：
  - 新增普通聊天流式授权续跑接口：`POST /api/chat/sessions/{sessionId}/tool-approval/stream`
  - 前端 `chatStore.resolveToolApproval()` 改为走 SSE，并复用现有的增量队列与稳定帧率刷新策略。
  - 用户授权后会先插入临时助手消息占位，后续正文与推理内容按流式增量持续渲染。
- 变更文件：
  - `server/src/main/java/com/aiagent/controller/ChatController.java`
  - `server/src/main/java/com/aiagent/service/ChatService.java`
  - `web/src/api/chat.ts`
  - `web/src/store/chatStore.ts`

### 10.2 修复刷新后仍停留在“允许/拒绝”的卡死体验
- 问题现象：
  - 用户已点击允许，但如果工具执行阶段网络断开或页面刷新，刷新后消息仍可能显示“允许/拒绝”。
  - 再次点击时，后端会返回“该工具调用已处理”，造成体验割裂。
- 修复方式：
  - 授权通过后，后端会先写入一条同 `toolCallId` 的 `tool` 消息占位，内容为“工具执行中…”，再真正执行工具并回写最终结果。
  - 因为会话中已经存在对应 `tool` 消息，页面刷新后不会再把该调用识别成“待授权”。
  - 前端若收到“该工具调用已处理”错误，会自动回刷当前会话消息与会话列表，而不是继续停在错误状态。

### 10.18 本轮补充（聊天页工具授权按钮错绑修复）
- 问题现象：
  - 当同一轮回答里已经完成过一段工具调用，随后模型又发起新一轮待授权工具调用时，聊天页会把这些工具块合并展示在一张卡片里。
  - 旧实现会把整张卡片的“允许/拒绝”按钮绑定到第一条 assistant 工具消息的 `assistantMessageId`。
  - 结果就是用户点击后端看到的是一条已经处理过的工具调用，SSE 会返回“该工具调用已处理”，前端刷新后看起来像“点了允许没反应”。
- 本轮修复：
  - 聊天页现在会为每个嵌入工具块记录其来源 assistant 消息 ID。
  - 当卡片里仍有未完成工具调用时，“允许/拒绝”会始终绑定到最近一条仍未产出结果的 assistant 工具消息。
  - 已完成工具调用的状态标签不再错误污染当前仍待授权的那一轮，避免出现“已允许”与待授权按钮同时出现的错乱状态。
- 实现文件：
  - `web/src/pages/ChatPage.tsx`
- 验证方式：
  - 使用 Chrome DevTools MCP 复查 `http://localhost:5173/chat/210`
  - 手工确认旧会话中第二次工具授权的点击目标与最新待授权 assistant 消息一致

### 10.19 本轮补充（思考侧栏流式结束后内容残缺修复）
- 问题现象：
  - 当用户在 assistant 仍处于“思考中”时打开右侧思考栏，侧栏会跟随流式增量不断更新。
  - 但流式结束后，右侧栏有概率停留在一份较早的半截推理快照上；关闭再重新打开后才会恢复完整内容。
- 根因分析：
  - 思考侧栏打开时记录的是“临时流式 assistant 消息”的负 ID。
  - 流式完成后，前端会移除临时消息并回刷正式落库消息，侧栏仍指向旧 ID，于是后续只会展示那份旧快照。
- 本轮修复：
  - 新增“思考侧栏消息匹配”逻辑：当侧栏仍指向临时消息时，会根据推理内容前缀、预览摘要和模型名，自动匹配到对应的正式 assistant 消息。
  - 一旦匹配成功，侧栏状态会把消息 ID 切换为正式消息 ID，并继续使用完整 `reasoningContent` 和 `reasoningDurationMs`。
  - 这样在流式结束的收尾阶段，右侧栏无需关闭重开，也能自然补齐最终完整内容。
- 实现文件：
  - `web/src/pages/ChatPage.tsx`
- 验证方式：
  - 使用 Chrome DevTools MCP 在聊天页发送带推理的消息并于流式阶段打开思考侧栏
  - 观察流式结束后侧栏内容保持完整，无需关闭重开
