# 文件实时同步 (File System Sync)

文件实时同步功能是 Open Zen 项目中心最核心、最复杂的技术模块之一。它通过 SSE 链路和 Java NIO WatchService 实现了前端编辑器与本地文件系统的双向感应。

## 链路架构 (SSE)

同步链路基于 **Server-Sent Events (SSE)** 实现，采用 `GET /api/projects/{projectId}/filesystem/stream?clientId=` 接口建立长连接。

### 核心机制
- **双端感应**：后端感知文件系统变化，通过 SSE 推送给前端；前端感知本地修改，通过 API 推送给后端。
- **ClientId 标识**：每个浏览器窗口/标签页拥有唯一的 `clientId`，用于识别变更来源，避免“回环”触发（即忽略自己引发的变更）。

## 监听策略

后端服务 `ProjectFilesystemWatchService` 使用 `java.nio.file.WatchService` 注册底层系统的文件监听器：

- **按需监听**：由于项目目录可能包含数万个文件，后端仅对 **当前已打开的文件** 和 **已展开的目录** 所在的父级目录进行监听。
- **兴趣注册**：前端定期通过 `POST /api/projects/{projectId}/filesystem/stream/interests` 接口，同步当前用户的“兴趣集合”（即 `openFiles` 和 `expandedDirs` 列表）。
- **动态注销**：当用户关闭文件或折叠目录时，后端会自动撤销不再需要的监听点，释放系统资源。

## 变更推送与处理

### 1. 监听事件 (StandardWatchEventKinds)
- **CREATE**: 新文件/目录创建。
- **DELETE**: 文件/目录被删除或重命名（移动）。
- **MODIFY**: 文件内容修改。
- **OVERFLOW**: 监听队列溢出，前端需执行全量刷新。

### 2. 推送策略
- **原子写入归并**：对于某些编辑器的“写临时文件 -> 重命名”写入模式，后端会识别并将短时间内的删除与创建动作合并为单次变更。
- **MODIFY 去抖**：对频繁的修改事件（如自动保存）设置 160ms 的去抖窗口，避免 SSE 通道拥塞。

## 冲突检测与数据一致性

### 1. Revision 比对
- **预期版本号**：每次读取或写入文件时，前后端会携带 `revision` 信息。
- **冲突拦截**：如果在写入时，后端的 `expectedRevision` 与本地不一致，说明文件已被外部工具修改。此时会拦截写入并提示用户解决冲突。

### 2. 自身保存过滤
- **抑制窗口**：后端收到来自某个 `clientId` 的写请求后，在 1800ms 的抑制窗口内，对该文件产生的相应监听事件不进行推送，防止编辑器因为感应到自己的保存动作而产生不必要的刷新或抖动。

## 异常处理

- **连接丢失**：前端检测到 SSE 连接断开后，会尝试自动重连。
- **大文件安全**：
  - **大文件检测**：通过 `GET /api/projects/{id}/filesystem/file/meta` 预检查文件大小。
  - **确认阈值**：文件超过 1MB 时，系统会弹出确认对话框，提示用户是否继续加载，以防止浏览器崩溃。
